# Support and Incident Ownership

Before controlled production use, assign named primary and backup owners for beta support, security reports, privacy requests, incident command, infrastructure, extension publishing, and customer communication.

## Operating expectations

- Publish one support intake channel and severity rubric.
- Define supported hours and response targets without implying an unapproved SLA.
- Give operators permission to pause schedules, disable a workflow, activate the kill switch, revoke sessions, and preserve evidence.
- Route repeated interventions into a stable failure class and product backlog item.
- Record support seconds through the approved aggregate metric; never place customer URLs, page content, credentials, or selectors in telemetry.

## Handoff record

Each release identifies the on-call owner, incident lead, rollback operator, Chrome publisher, privacy contact, and customer-communication owner. `support-incident-ownership` remains pending until every role has accepted and the contact path has been tested.
