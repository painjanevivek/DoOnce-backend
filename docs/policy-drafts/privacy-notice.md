## What this notice must explain

DoOnce provides tenant-scoped browser-workflow tooling for reviewed, low-risk tasks. Before publication, this notice must state plainly which product, organisation, markets, and processing activities it covers.

## Data categories and purpose

| Category | Purpose | Product boundary |
| --- | --- | --- |
| Account and tenant details | create accounts, sign in, administer access, and provide support | email, tenant name, user ID, and role only as needed |
| Session/security data | secure authentication, abuse prevention, and incident investigation | signed session identifiers, token hashes, request metadata |
| Workflow definitions and audit events | save reviewed workflows and show accountable lifecycle history | version identifiers, actor, timestamp, event type, aggregate counts |
| Support correspondence | answer a user-approved support request | redacted diagnostic material only |

DoOnce must not intentionally collect passwords, OTPs, payment credentials, browser page content, or action values in workflow audit events. Any future feature that changes these categories requires a privacy review before implementation.

## Required completed sections before publication

- legal basis, consent wording where applicable, and whether automated decisions are made;
- recipients, subprocessors, storage locations, and transfer safeguards;
- retention schedule and deletion process;
- rights-request method, identity verification, response handling, and complaint route;
- age/children policy and region-specific notices; and
- version history and material-change notice process.

The final notice must be concise, accessible, and explain the controller, purpose, categories, retention, recipients/transfers, and rights in the markets where DoOnce operates.
